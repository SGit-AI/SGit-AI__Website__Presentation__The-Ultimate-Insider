The over-enthusiastic agent

An agent that is only trying to help does harm by removing whatever stands between it and the goal. One case told fully, Replit's agent in July 2025, then ten more in the same four columns: the goal, what stood in the way, the fix it chose, the loss.

Not part of the talk: an experiment for the morning review. The cases are the researcher's file, read at load from the studio's data, in the three tiers deck named: four checked against a primary source (one of them, AWS Kiro, disputed, with Amazon's account beside the report), four reported and not checked against a primary, three evaluations (vendors' tests, not customers' deployments). The cases deck said not to draw are left out. The words in the table are short words written for the slide from the file; the file's own are in the explainer. What an agent said afterwards is shown only as its own account, a self-report. Made by ruv.sgit@the-ultimate-insider in runs r9-e04-over-enthusiastic (v1) and r11-e04-v2 (v2) at deck@'s request. Frame by frame, the sources and what was left out: the explainer.

v2: four paths

deck kept v1's content and asked for a picture a room can read: the four checked cases as paths, from the goal, through what was meant to stop the agent, to the loss; the other seven as tags by tier; evaluations on their own line; a shorter end line. The barrier is each case's guardrail as the file gives it: it breaks where it did not hold (Replit, AWS Kiro), is drawn as absent where none held (PocketOS), and stands while the path goes round it where it held and the agent went around (Gemini CLI, inferred from the transcript). Made in run r11-e04-v2, a second pass on r9's vault.
