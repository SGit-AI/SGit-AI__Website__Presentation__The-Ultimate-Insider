What an agent is, frame by frame

The one sentence the piece must carry: an agent is a chat model that was given tools, then more tools, then a loop, then our accounts, and each step added reach. Both versions keep every earlier step on screen, so the eye follows the growth, not a sequence of separate pictures.

What is stated, and the source behind it

  • The loop. "LLMs using tools based on environmental feedback in a loop": Anthropic, Building effective agents, the talk's own source for the definition. Quoted on screen in both versions.
  • The order of the steps is the request's, and it is a sketch: no dates are shown, because a date on each step would need its own public source. Both versions say so on screen.
  • No numbers. The size of each ring and of the shaded reach is illustrative, and both versions say so on screen. Nothing on screen counts anything.
  • Nothing on screen names a product, and nothing says any product is unsafe. Nothing forecasts.

Technique

  • v1, built. SVG and the slide engine's declarative reveals: data-in for each ring and label, data-on for the step list, data-draw for the loop ring, and one small SLIDE_RENDER for the dot that runs round the loop. Labels carry a halo in the background colour so they read over the rings.
  • v2, driven. One canvas, redrawn every frame by SLIDE_RENDER from the slide's clock, so the player can seek, pause and replay it and ?t= freezes any moment. Colours are read from the site's tokens, so both themes work.
  • Both are standalone lab pages on the engine (1280 by 720), with no script from another host. With reduced motion the engine shows the end state, which makes the point on its own.

What was tried and left out

  • Dates on the steps. Left out: each would need a public source, and the request allowed a sketch instead.
  • A count of what the agent can touch, growing at each step. Left out: any count would be invented, and a number on screen invites a question the piece cannot answer.
  • Joining "our systems" through the tools in v2. Tried first; the crossing lines made the end state unreadable, so the systems join the model directly.
  • A larger reach in v2 ran into the headline and pushed the other agents off the canvas; the geometry was tightened.
  • Three colours of meaning. Both versions draw meaning in the agent red only (this is the agent's story), with the heading colour for labels and the theme's panel colours for fills; the teal in the headline is the slide engine's own emphasis.

How it was made

In ruv.sgit run r3-e01-agent-evolution: a Ruflo hive with four workers (v1, v2, this explainer, and an editor who checked all three against the request), and one sgit vault holding the request, each worker's branch and the history. Its row is in the ledger; how runs work is in How ruv.sgit works.
