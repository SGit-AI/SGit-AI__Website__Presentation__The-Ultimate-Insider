Studio experiment E10 · the explainer

Only a boundary is a control, frame by frame

The one sentence: of the four kinds of barrier an Agent Behaviour Policy records per capability, only a boundary bounds anything, because only a boundary is enforced by something the grant does not include. Claude Code's confirmations are a setting: turning them off moves one row's barrier and changes no count.

The row that moves

The slide compares the two examples' rows capability by capability and draws every row whose barrier_kind differs. Exactly one does:

CapabilityConfirmations onConfirmations off
Run programs as the account
execute.process.host, in the mandate		setting: the tool's own directory restriction and its confirmation prompt, enforced by the tool, which runs inside the grant; anything that can execute as you steps around itnone: none, confirmations disabled; the tool runs whatever it decides to run

Why no count moves, in the data file's own note: the row "is in the mandate (aligned), which is why no count moves." The other setting row, "the settings file is owned by the same account" (grant.credential.self), stays at setting in both. The single expectation row is write.repository.tenant, "branch discipline in prose, if any".

Where every word comes from

  • The four kinds, their order, their published meanings and which one is a control: barrier_kinds in abp-examples.json (abp.sgit.ai's barriers.json). The verdicts under the walls read is_control; the file notes that is_control and its "why" are abp.sgit.ai's own reading, and the claim that three of the four kinds bound nothing is a definitional position by one author, shown as a position, not graded as a fact.
  • The two lines from the model: the barrier's definition and the enforcer test, quoted.
  • The rows and counts: the two examples' rows, counted per barrier kind on the slide; the numbers in the table are each example's own fields (grant, mandate, excess, unbounded_excess, irreversible), compared on both.
  • The example names under the headline are the file's: "A coding agent on your own machine, confirmations on" and "The same coding agent, confirmations off"; the heading "Claude Code" is from each example's agent field.
  • The label of the row that moves, "Run programs as the account", is capabilities.json's.
  • The end line is the data file's claim abp-cc-one-barrier-moved, checked by its author by diffing the two raw profile files.
  • The caution: both examples are derived, 0 of 22 tool-level rows measured; the mandate is the site's own first draft; both sites are one author's network. No score, rating or traffic light, as the model's own rule says.
  • Words the slide adds: "the agent", "not a control", "a control: holds", "none here", "row moves", the column headings. Each restates a field (is_control, an empty row count), not a new claim.

Technique

  • One slide on the engine, driven: the SVG and the table are built once from the two data files, then every frame is drawn from the slide's clock by SLIDE_RENDER, so the player can seek, pause and replay it, and ?static shows the end state. The stages are declared in window.RUV_STEPS: 0, 9, 24, 33 and 41 s.
  • E04 v2's language for a path at a wall: the path draws itself, and where it gets past it jumps or breaks the wall and changes colour; the boundary is the one wall it does not get past.
  • Three colours of meaning: the agent's red for the agent and its path past a wall, the accent for the one kind that is a control, amber for the row that moves. Everything else is neutral. Every text is 20 px or larger on the 1280 by 720 canvas; both themes (?theme=light).
  • It runs only over HTTP. The slide reads both files with fetch when it loads; opened as a file from disk it shows only the headline.

What was tried and left out

  • The "why" of each kind on screen: too much text beside four walls; it is in the data file, and the enforcer test carries it in one line.
  • An example with a row at a boundary. Neither Claude Code example has one, so the slide says "none here"; the CI runner example, the only one with a boundary row, is outside this request's data and left for E13.
  • The full row control texts on the slide: long; they are in the table above.
  • A dot per row labelled in place. Sixteen labels at 20 px do not fit; only the row that moves is named in the drawing.
