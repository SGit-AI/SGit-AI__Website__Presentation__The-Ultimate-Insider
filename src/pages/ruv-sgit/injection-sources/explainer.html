Studio experiment E03 · the explainer

Every source is a way in, frame by frame

The one sentence: everything an agent reads is a way in, because the words in it can steer the agent. E02 showed how far one agent reaches; E03 shows how many doors the words come through.

Where every word comes from

Only from injection-sources.json, the researcher's capture for the studio, read by the slide when it loads, so a corrected file corrects the slide. Each source's source, and its case's title, date, label, impact and note where it has one, are shown as the file gives them; the counts in the key and the end line are counted from the file.

  • No payload. The file never quotes the words that steered an agent, and neither does the slide or this page.
  • Labelled, as the file asks. Each dot's shape is its case's label: filled for a real-world incident, a ring for a vendor-confirmed vulnerability, a dashed ring for a research demonstration. Eight of the sixteen are demonstrations, and the slide does not present them as attacks seen in the wild.
  • One source each. The file's caution, kept on screen at the end: no case has an independent second primary source.
  • No code comment. The file found no public case of a code comment steering an agent; rules files and READMEs are the nearest, and the code row is a pull request. The end line says so.
  • Holds in part. ClawHavoc (14) carries the file's note, shown with it on the slide: the words steered the users, not shown to steer the agent.
  • The families are this piece's. Sent to it, it browses, it builds with, other agents give it: a grouping by how the words reach the agent, made for the slide. The file lists the sixteen without groups.

Technique

  • One slide on the engine, driven: SVG built once from the data, then every frame drawn from the slide's clock by SLIDE_RENDER, so the player can seek, pause and replay it, and ?static shows the whole picture.
  • One colour of meaning, the agent red, for the way in; the label is carried by shape, not colour. Every text is 20 px or larger on the 1280 by 720 canvas.
  • It runs only over HTTP. The slide reads its data with fetch when it loads, so opened as a file from disk it shows the frame and no ring; on the site, or any local web server, it works.

What was tried and left out

  • Case names on the ring. Sixteen titles round a circle at 20 px do not fit; the ring carries numbers and the list carries the sources, with the case named in the line under the headline as each one lights.
  • A larger ring ran into the key at the bottom and pushed a family name off the left edge; v1 uses a smaller one.
  • What it read, then what it did. The request asked for both; the file gives each case's impact in one line and its fuller account in what_happened, which does not fit under the headline at 20 px, so the slide shows the impact and leaves the account to the file.
  • Colour per family. Four families plus three labels would be seven colours; the families are told by position and name instead.

How it was made

v1 in ruv.sgit run r8-e03-injection-sources: a Ruflo hive with a builder and an editor who checked the slide and this page against the request and the data, and one sgit vault holding the request, each worker's branch and the history. Its row is in the ledger.
