The programme

A whole new set of visualisations to tell the story. Part one shows the threat: what an agent is and how it grew, how far one internal agent reaches, how soft the inside is, and how injected words travel. Part two shows the way out: map the mandate against the grant, type every barrier honestly, and contain the agent with boundaries it cannot reach, using RiskMandate's Agent Behaviour Policies and SHarness, with many real examples.

These are experiments, not slides. The talk itself is frozen; nothing here changes it until the editor picks what to keep.

How it runs

  1. deck writes each experiment's question and idea here, and asks the makers for it by request.
  2. The conductor paces the queue: one experiment in flight with each maker at a time, in the order below unless the editor reorders it.
  3. The researcher supplies the data, graded and captured; ruv.sgit makes the piece in a run.
  4. deck reviews every pass and asks for another, or marks it for the editor.
  5. The editor reviews in the morning: keep, change or drop.

Every experiment comes back as

  • the piece itself, on the slide engine, at ruv-sgit/<slug>/index.html (ruv.sgit's pages)
  • an explainer beside it, ruv-sgit/<slug>/explainer.html: what it shows, frame by frame, the data and sources behind each frame, and what was tried and left out
  • the run's ledger row: what it cost and what the vault holds
  • deck's review at studio/reviews/<id>.html: what works, what does not, and what the next pass is

    What an agent is: the evolution

    How did a chat window become an insider?

    Start small: a chat model answering in a box. Give it one tool. Then more tools. Then a loop, so it acts until it decides it is done. Then integrate it: accounts, tokens, other systems. Then today's agentic flows, agents calling agents. Each step adds reach, and the picture keeps the earlier steps visible so the growth reads.

    When is an agent dangerous by construction?

    Three switches: private data, untrusted content, a way to send outward. All three on and a document can turn the agent. Turn any one off and that path closes.

  2. E10 · idea · order 10

    Only a boundary is a control

    What actually stands between the agent and each thing it can do?

    None, expectation, setting, boundary. Most of what we call controls are expectations or settings the agent's own account can flip. The test: a control bounds a grant only if it is enforced by something the grant does not include. Turn the confirmations off on Claude Code: one barrier moves, and not one number does.

    Data. riskmandate.ai/abp.html: the barrier table and the confirmations on and off example; abp.sgit.ai/data/barriers.json

  3. E11 · idea · order 11

    SHarness: the kernel was told first

    How do you make a boundary the agent cannot widen?

    Write the process behaviour policy, hash it, hand it to the kernel before the tool starts. Then the six probes of sharness-ai hello: reads allowed; a write outside the workspace, a connect and an oversized allocation refused; a wrong hash runs nothing. Six of six held (25 October 2026). And the honest caveat: a process cannot bind its own session; the launcher above the agent is designed, with a first slice running since 28 October.

    Data. sharness.ai via the researcher: src/static/studio/data/harness.json (hello: six of six held, 25 October 2026, five environments on two kernels; component status labels)
